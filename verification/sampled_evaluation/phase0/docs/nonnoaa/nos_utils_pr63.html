Description

This makes the STOFS-3D-ATL dynamic SSH adjust compute today's bias the way ops v3.1 does. Until now the port never computed it: every cycle applied adj1 = 0.

Found on WCOSS2 with a standalone prep for PDY 20261001 12z, seeded with the ops 0930 staout_1, param.nml and avg_bias:

  • adj0 was read correctly: -0.037, the same as ops.
  • No observations loaded at any of the 11 stations, so today's bias was NaN and 0 was applied (ops: -0.039).
  • elev2D therefore differed from ops rerun/stofs_3d_atl.t12z.elev2dth.nc by exactly 0.039 m from hour 2 onward.

There were two bugs:

  1. Observation format. The dcom files $DCOMROOT/<PDY>/coops_waterlvlobs/<id>.xml are space-separated text, e.g. 8670870 1 WL 2026-09-24 00:00 1.261 0.003 1 0 0 0. Ops reads fields 4, 5 and 6 with awk, then create_npz_NOAA.py converts them. The port looked for XML t="..." v="..." attributes and matched nothing.
  2. Model columns. derive_bias.py looks each bias station up by ID in the full model station.in (166 rows); the 11 stations are rows 10, 11, 13, 14, 18, 19, 21, 22, 23, 24, 26. The port used staout_1 columns 1-11, by position in the bias station list.

What changed (nos_utils/forcing/dynamic_adjust.py, nos_utils/orchestrator.py):

  • Observations. The dcom text is parsed as ops does:
    • time = field 4 + field 5, value = field 6;
    • a file with fewer than 10 lines is skipped;
    • a row with an empty field 6 is skipped;
    • no QC-flag filtering.
      The old XML-attribute parsing is kept as a fallback.
  • Station mapping. Each bias station's staout_1 column comes from its row in the model station.in. The orchestrator finds that file in the fix dir as <run>.station.in, stofs_3d_atl_station.in, <run>_station.in or station.in. If station.in is missing, or a station is not in it, there is a warning and no positional fallback.
    • The full <run>_station.in is no longer a candidate for the 11-station bias list.
  • Numerics as ops.
    • The bias is rounded to 3 decimals, as ops writes it and reads it back.
    • The hour-1 offset is (adj0 + adj1) / 2 truncated to 5 decimals, as bc scale=5 does.
    • The offsets are subtracted in float32, as ncap2 does.
  • Failure cases as ops. In each of these, ops ends up applying adj1 = 0; the port now warns and does the same:
    • previous staout_1 under 10000 bytes;
    • missing or unreadable diff.bp;
    • a bias station with observations but no diff.bp entry. The port used to apply a zero datum offset silently here, which gave -0.431 m in a test where ops gives 0.
  • Archive file. The bias is also written as <run>.t<cyc>z.avg_bias, with 0.0 when today's bias is NaN, as ops archives it in rerun/. The next cycle already prefers this name. average_bias_today is unchanged.

The window (PDY-2 12:00 to PDY 12:00), gap interpolation, hourly averaging and the 20% NaN rule already matched ops and are unchanged. The previous-cycle inputs still come only from COMINrerun; wiring them in nos-workflow for normal cycling is a separate change.

Type of change

  • Bug fix (non-breaking change that fixes an issue)

Change characteristics

  • Changes outputs (values, COMOUT files or names, archives)? YES, for STOFS-3D-ATL only:
    • elev2D.th.nc gets the observed bias (adj1) when the previous-cycle files are available;
    • a new <run>.t<cyc>z.avg_bias file is written next to average_bias_today.
  • Breaking change to existing functionality? NO. Dynamic adjust is enabled only for STOFS-3D-ATL; SECOFS, AK and Pacific are unchanged.
  • Requires a nos-utils submodule bump (nos-workflow) or a paired nos-workflow change (nos-utils)? YES. A submodule bump picks it up. Normal cycling also needs nos-workflow to pass the previous cycle's staout_1, param.nml and avg_bias via COMINrerun, which is a separate PR.
  • Requires new or regenerated fix files on the machine? NO. It uses the existing stofs_3d_atl_ufs.station.in, stofs_3d_atl_obc_adjust_station.bp and stofs_3d_atl_obc_adjust_msl_geoid.bp.
  • Requires a re-prep or a new hotstart before the next cycle? NO.
  • Machines affected: both

How has this been tested?

  • pytest: 1057 passed, 4 skipped. The new tests cover:
    • real-format dcom rows (flag-0 kept, short row dropped, 9-line file skipped);
    • station mapping with the bias stations away from the first rows and decoy values elsewhere;
    • rounding, the bc average and float32 subtraction;
    • the staout_1 size gate, missing or incomplete diff.bp, and both bias files;
    • a numpy mode helper checked against scipy.stats.mode, including ties.
  • Independent parity harness: the real ops ex-script, create_npz_NOAA.py and derive_bias.py, with the ops pylibs and NCO, run side by side with the port.
    • Inputs: synthetic dcom files and a 166-column staout_1, with the real ops station.in, station.bp and msl_geoid.bp.
    • Scenarios:
      • month and year crossings;
      • gaps, a station over 20% missing, a short file and an absent file;
      • previous bias present, NaN or absent;
      • staout_1 intervals of 150, 300 and 600 s;
      • 16 randomized cycles.
    • Results: the bias is identical in every scenario, and the adjusted elev2D is bitwise identical to the ops ncap2 output.
  • WCOSS2 Python compatibility: the prep runs Python 3.8.6 with numpy 1.20.1, scipy 1.6.2 and pandas 1.2.3. A first WCOSS2 re-run failed because scipy.stats.mode(..., keepdims=False) (copied from ops derive_bias.py) needs scipy 1.9 or later, which left the bias NaN. The mode is now computed with numpy, with the same smallest-most-frequent rule.
    • In an environment pinned to those versions, tests/test_dynamic_adjust.py gives 53 passed (8 failed before the fix).
    • The parity harness, with the port run in that environment, gives identical biases and bitwise-identical elev2D, the same as in the main environment.
  • WCOSS2: standalone prep for PDY 20261001 12z with this branch (merged locally with STOFS-3D-ATL standalone sflux: GFS chain, PRATE, true grid and HRRR winds as ops #64), with the previous cycle seeded from ops 0930 (staout_1, param.nml, avg_bias):
    • log: adj0=-0.0370 adj1=-0.0390 avg=-0.0380 in both phases (ops 1001: yesterday -0.037, today -0.039);
    • adjusted elev2D vs ops rerun/stofs_3d_atl.t12z.elev2dth.nc, nowcast (31 hourly records) and forecast (103): max diff 5.96e-8 m, RMS 1.5e-8 m, 78% of values bit-identical. That is the last float32 bit, the same level as the non-adjusted boundary.
    • Before this change: 0.039 m from hour 2 onward, the missing adj1.

Figures (PDY 20261001 12z, WCOSS2 standalone preps before and after this change vs ops rerun/; script in mansurjisan/My_Scripts, STOFS-3D-ATL-V31-VALIDATION/plot_dynadj_compare.py):

Boundary SSH (elev2D) at four nodes along the open boundary. The ops non-adjusted SSH is held constant in time, so the adjustment steps are the whole signal. Before this change adj1 was never computed and applied as 0, so the boundary sat 0.039 m below ops from hour 2. With this change it matches ops to 6e-8 m.

Offset applied in the first hours: ops and this change step through -adj0 (+0.037 m), -(adj0+adj1)/2 (+0.038 m) and -adj1 (+0.039 m). Before, the offset dropped to 0 from hour 2.

Bias at the 11 NOAA gauges over 09-29 12Z to 10-01 12Z: the previous ops run (staout_1, columns found by station ID in station.in) against observed water level plus the datum offset. All 11 gauges pass the 20% NaN check. The average is -0.0388 m, rounded to -0.039 m, equal to the ops avg_bias.

The bias interpolation called stats.mode(dt, keepdims=False), which does not
exist before scipy 1.9, so every station failed with an unexpected keyword
argument on the WCOSS2 python 3.8.6 / scipy 1.6.2 modules and today's bias
fell back to NaN.

_mode returns the smallest of the most frequent values via np.unique counts,
which is what scipy.stats.mode returns. A test compares it with scipy.stats.mode
on tied, float-day and gappy-record arrays. The dynamic adjust tests were also
run on python 3.8.6, numpy 1.20.1, scipy 1.6.2, pandas 1.2.3, netCDF4 1.5.6.
